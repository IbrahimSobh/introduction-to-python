Part A

Python basics

A program is a list of instructions, run top to bottom

  • Python reads almost like English: one of the easiest languages to learn, and one of the most widely used
  • The computer follows a program one line at a time, from top to bottom
  • print() shows values on the screen: print(2 + 3) shows 5
  • A line starting with # is a comment: a note for humans that Python skips
Python runs your lines in order, one at a time, from top to bottom.
Analogy: a recipe. Each step is simple and the order matters. print() is a ready-made command, which Python calls a function (lesson 7 shows how to write your own). Text goes inside quotes; numbers don't. Several items separated by commas are printed with a space between them. Python is used for data and AI, websites, automation scripts, science and teaching.

Keep programs in .py files; use the REPL as a calculator and to test ideas.
Install Python from python.org; on Windows tick "Add Python to PATH". Check with python --version (python3 on macOS or Linux). Editors: VS Code with the Python extension, PyCharm (an IDE with a debugger), Jupyter notebooks for data work, or IDLE, which comes with Python. REPL stands for Read, Evaluate, Print, Loop. Leave it with exit(). In the REPL, text values are shown with quotes; print() shows them without.

A variable is a name that refers to a value

  • age = 21 stores 21 and sticks the label age on it
  • Writing age later means "the value in that box"
  • Give the label a new value and it simply moves
  • Names: letters, digits and _; can't start with a digit; case-sensitive; no keywords like if
= stores a value under a name; using the name reads it back.
Analogy: sticky labels on boxes. Good names say what the value means: price beats p. score2 is fine, 2score is not; use user_name, not user name or user-name. age and Age are two different names.

Every value has a type that decides what you can do with it

TypeWhat it holdsExamples
intwhole numbers7, -3, 2025
floatnumbers with a decimal point3.14, 2.0
strtext, inside quotes"hello", '42'
boolyes or noTrue, False
None"no value yet"None
The type, not how a value looks, decides what Python can do with it: '42' is text.
The names are short for integer, floating-point number, string (a string of characters) and Boolean (after the mathematician George Boole). None's type is called NoneType. Ask Python for any value's type with type(): type(3.14) gives <class 'float'>.

input() always gives text: convert it before doing maths

  • input() waits for the user and always returns a str, even if they typed digits
  • Convert with int() or float(); turn a number into text with str()
  • "5" + 3 is a TypeError: Python won't add text to a number
  • int("5") + 3 gives 8; "5" + str(3) gives '53'
Data from users, files and websites arrives as text. Convert it first.
int(3.5) is 3: it cuts the decimal part off and does not round. int('abc') stops the program with a ValueError (lesson 9 shows how to handle it). bool(x) gives False for 0, 0.0, empty text and None, and True for everything else.

Python works an expression out one operator at a time

  • An expression is anything Python can work out to a single value
  • 2 + 3 * 4 → 2 + 12 → 14: * comes before +
  • / always gives a float (7 / 2 is 3.5)
  • // is whole-number divide, % the remainder: 7 // 2 is 3, 7 % 2 is 1
Same rules as school maths. When in doubt, add brackets.
Working out an expression is called evaluating it. 7 ÷ 2 is 3 with 1 left over (3 × 2 + 1 = 7), so 7 // 2 is 3 and 7 % 2 is 1. If either number is a float, the result is a float: 10 - 2.0 is 8.0. (2 + 3) * 4 is 20. 2 ** 3 is 2 × 2 × 2 = 8. Operators on the same row of the ladder go left to right (except **).

Comparisons and logic answer yes-or-no questions

  • Comparisons == != < > <= >= give True or False: 5 > 3 is True
  • and: True only if both sides are True
  • or: True if at least one side is True
  • not: flips True and False
  • One = stores a value; two == ask a question
Comparisons and logic turn questions into True or False, ready for decisions.
n % 2 == 0 is True for even numbers. 5 > 3 and 2 > 4 is True and False, which is False. These yes/no answers drive the if statements in lesson 5: if age >= 18 and has_ticket:

A string is a row of characters, numbered from 0

  • s[0] is the first character, s[-1] the last
  • s[start:stop] goes up to but not including stop: "Python"[0:2] is 'Py'
  • Leave a number out for "from the start" or "to the end": s[:3], s[2:]
  • A step: s[::2] is 'Pto', s[::-1] is 'nohtyP'
Indexes start at 0, and a slice stops just before its stop index.
Analogy: a row of letter tiles with numbers underneath. For a negative index, Python adds the length: in "Python" (6 characters), -1 means 6 - 1 = 5. Strings can't be changed in place: s[0] = "J" is an error; make a new string instead.

String methods give back new strings; f-strings build text

MethodExampleResult

Methods never change the original string; f-strings are the easiest way to build text.
A method is a command that belongs to a value; you call it with a dot: text.upper(). len(s) counts characters (a built-in function, not a method). Each method returns a new string, so calls chain: answer.strip().lower() cleans what users type. line.split(",") splits a line of a CSV file into its values. The f-string example assumes name = 'Ada' and score = 9.
Part B

Decisions and data

5Control Flow6Data Structures

if / elif / else: the first true condition wins

  • A condition is an expression that is True or False, such as age >= 18
  • Python checks the conditions from the top and runs the block under the first True one
  • else runs only when none of them were True
  • Indentation (4 spaces) is how Python knows which lines are inside a block
Only one branch runs: the first condition that is True.
Analogy: a junction on a road; you take one road depending on a condition. elif means "else if" and is checked only when every condition above was False. The diagram is the program the lesson's demo steps through, shown for n = 4.

Loops repeat a block: for over items, while until a condition is False

  • for n in range(1, 5): repeats for 1, 2, 3, 4 (stops before 5)
  • while condition: repeats as long as the condition stays True
  • break leaves the loop now; continue skips to the next round
  • A while loop must change something, or it runs forever
Use for when you know what to loop over; use while to repeat until something happens.
Analogy: a roundabout; you go around until it's time to exit (break), and sometimes skip ahead to the next lap (continue). Each pass is a round (or iteration). count = count - 1 works out count - 1 first, then stores it back, so a countdown reaches 0 and stops. Press Ctrl+C to stop a program stuck in a loop.

Four collections, four jobs

Ordered?Can change?Duplicates?
list ["a", "b"]yesyesyes
tuple (3, 4)yesnoyes
dict {"Ada": 36}keeps insertion orderyeskeys are unique

Each collection is good at a different job: pick by what you need to do.
Analogies: a list is a shopping list, a tuple a date of birth (fixed once written), a dict a phone book (look up a number by a name), a set a bag of unique stickers. "Ordered" means items stay in the order you put them in, not that they get sorted. Changing a tuple (point[0] = 10) raises a TypeError. Everyday operations: append(), pop(), ages[k] = v, ages.get(k) (None if missing), colors.add(x), x in colors.

Choose the collection that fits the job

  • Order matters and items change → list
  • A fixed group of values → tuple
  • Look a value up by its key → dict
  • Only unique items → set
Order and change → list; fixed → tuple; look up by key → dict; unique → set.
More examples: a playlist in play order is a list; a phone book is a dict; settings, word counts and JSON data from the web (the text format websites use to send data) are dicts. Sets remove duplicates and answer "have I seen this?" quickly. A list comprehension builds a list in one line: [n * n for n in range(1, 6)] gives [1, 4, 9, 16, 25], the same as a three-line loop with append().

Building programs

A function: define it once, call it as often as you like

  • def starts a definition; the indented lines are its body
  • Defining does not run it; calling does: greet("Ada") gives 'Hello, Ada!'
  • Arguments fill the parameters in order; defaults fill in what's left out: area(3) uses height=1
  • return hands a value back; print() only shows it
A function packs one job behind a name, so you write it once and reuse it.
Analogy: a coffee machine. You press a button with inputs, it works inside, and hands you a result; you don't need to know what happens inside. In area(3, 4), width is 3 and height is 4. A function with no return gives back None. Fix a bug once inside a function and every call gets the fix.

Names created inside a function are local to that call

  • Each call gets its own box of local names, which disappears when the call returns
  • Names at the top level of the file are global
  • A function can read a global name; outside code can't see a function's local names
  • Prefer parameters in and return out over changing globals
Local names live only while their call runs.
This is what the lesson's demo animates: the purple box appears for each call and vanishes when it returns. After greet("Ada") returns, its local names are gone and text holds 'Hello, Ada!'. Changing global variables from inside functions (with the global keyword) makes programs harder to follow.

Modules: import ready-made code instead of writing it

You writeThen you useGood when
import mathmath.sqrt(16)the usual choice: it's clear where sqrt comes from
from math import sqrtsqrt(16)you use one or two names a lot
import datetime as dtdt.date.today()the module name is long
A module is a .py file of ready-made code; import loads it.
Analogy: Python comes with a big toolbox, the standard library, with a drawer for each kind of job. Put imports at the top of the file. Avoid from math import *: it dumps every name into your program. Every file you write is a module too. pip install (Python's installer for extra packages) adds packages such as requests or pandas, imported the same way.

The standard library already does the common jobs

  • math: math.pi, sqrt(); floor(3.7) is 3, ceil(3.7) is 4
  • random: randint(1, 6) like a die (both ends included), choice(), shuffle(), sample()
  • datetime: date.today(), plus timedelta(days=7) for a due date
  • More: files (os, pathlib), the web (urllib), data (json, csv)
Before writing it yourself, check the standard library.
sqrt() of a negative number raises a ValueError. sample(list, k) picks k different items in random order; the final project uses it to choose the questions. Adding 7 days to a date handles month and year changes for you.

Read a traceback from the bottom up

  • The last line names the error and what went wrong
  • The lines above show the path, ending at the exact line that failed
  • Common errors: SyntaxError, NameError, TypeError, ValueError, IndexError, KeyError, ZeroDivisionError
Start at the last line, then go to the line number it points to.
When Python hits a problem while running, it stops and reports an exception, and says the line raised it. In this example, cart is an empty list, so len(items) is 0. The fix: return early (for example return 0) when the list is empty. Debugging steps: read the last line, print what you think you know (print(x, type(x))), make it smaller in the REPL, use a debugger's breakpoints, or explain it out loud (rubber-duck debugging).

try / except lets a program recover instead of crashing

  • Put code that might fail inside try
  • An error jumps to the except block that names its type, such as except ValueError:
  • finally runs at the end every time, error or not
  • 10, 2 → Result: 5.0 · 10, abc → ValueError · 10, 0 → ZeroDivisionError
Plan for the errors you expect, and the program keeps going.
Analogy: a smoke alarm. The exception is the alarm going off, the traceback tells you which room, and the except block is your plan for when it rings. Typical uses: asking again when someone types letters instead of a number, files that might be missing, network calls that might fail; finally for closing a file or connection.

Key takeaways

  1. A program runs line by line, top to bottom; print() shows values.
  2. A variable is a name for a value; every value has a type.
  3. input() gives text: convert before doing maths.
  4. Expressions follow precedence: 2 + 3 * 4 is 14.
  5. Strings are indexed from 0; slices stop before the stop index.
  6. if / elif / else runs the first true branch; loops repeat a block.
  7. list, tuple, dict and set each fit a different job.
  8. Functions: define once, call often; return hands back a value.
  9. import ready-made modules instead of writing them.
  10. Read tracebacks from the bottom; try / except recovers.
